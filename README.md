# Camille Lin — Portfolio

Personal portfolio built with Next.js 16 (App Router), TypeScript, and Tailwind CSS. Static, no database, no auth, no CMS. Owned entirely through personal accounts (GitHub, Vercel, and optionally a personal domain) and designed to keep working after any employer-provided account or tool becomes unavailable.

## Routes

| Path | Page |
|---|---|
| `/` | Homepage |
| `/resume` | Accessible HTML resume (same content as the PDF, with a "Download PDF Resume" action) |
| `/resume/camille-lin-resume.pdf` | Downloadable resume PDF (static asset) |
| `/work/requirements-governance` | Requirements Governance Dashboard |
| `/work/qa-data-platform` | QA-Owned Operational Data Platform |
| `/work/accessibility-enablement` | Accessibility Enablement System |
| `/work/reporting-automation` | Reporting Automation & Data Pipeline |
| `/sitemap.xml`, `/robots.txt`, `/opengraph-image`, `/icon.svg` | Auto-generated by Next.js file conventions |

The header and footer "Resume" links point to `/resume`, the accessible HTML version; that page then offers a clearly labeled "Download PDF Resume" action for the PDF itself.

All project content on this site is a public-safe, sanitized representation of real work. Every dashboard, table, chart, identifier, and figure shown is fictional and labeled **"Synthetic portfolio data"**.

## Tech stack / external dependencies

- [Next.js 16](https://nextjs.org/) (App Router, static generation) — the current stable release, linted with ESLint 9 (flat config)
- [React 18](https://react.dev/) / TypeScript 5 / Tailwind CSS 3
- Fonts: **Outfit** and **Instrument Sans**, both open-source under the SIL Open Font License. The actual font files are bundled locally in this repository under `public/fonts/` and loaded via `next/font/local` — the build does **not** fetch anything from Google Fonts (or any other external font host) at build time or at runtime. License text for each family is included alongside the font files (`public/fonts/outfit/OFL.txt`, `public/fonts/instrument-sans/OFL.txt`).
- No database, no auth provider, no CMS, no analytics SDK is wired in.
- No required environment variables. One optional variable is supported — see "Production URL configuration" below.
- The downloadable resume PDF is generated with [WeasyPrint](https://weasyprint.org/) (Python) from the site's own semantic HTML and a dedicated print stylesheet — not ReportLab, and not a screenshot/print-preview of the live site. See "Regenerating the resume PDF" below. WeasyPrint itself is a build-time tool only; it is not a runtime dependency of the deployed site and adds nothing to the production JS bundle.

## Production URL configuration

This project does not hardcode a production domain, since a personal domain may not be confirmed yet. `lib/site.ts` resolves the public site URL at build time in this order:

1. **`NEXT_PUBLIC_SITE_URL`** — set this in your Vercel project's Environment Variables once you know your real production address (your `*.vercel.app` URL, or a custom domain if you add one later).
2. **`VERCEL_URL`** — Vercel automatically sets this on every deployment (production and preview) to the correct address, so a build on Vercel is always correct even before step 1 is configured.
3. `http://localhost:3000` — used only during local development, never in a production build.
4. `https://example.com` — a last-resort placeholder (the IANA-reserved example domain) if a production build somehow runs with neither variable set. This value can never be mistaken for a real, owned domain.

**What to do after your first Vercel deployment:** open your Vercel project → Settings → Environment Variables → add `NEXT_PUBLIC_SITE_URL` set to the URL Vercel assigned you (or your custom domain once one is attached) → redeploy. This keeps canonical links, the sitemap, and Open Graph/Twitter metadata accurate.

## Dependency security

`npm audit` is reviewed as part of every release. The deployed site is a fully static Next.js App Router app: it uses no `next/image`, no Middleware, no `rewrites`, no Server Actions, no custom server, and no i18n. The only dynamic route is the on-demand Open Graph image.

- **`next`** — runs on `16.2.11`, the current stable release. Next.js itself reports **no** unresolved high-severity advisories at this version, so the framework the public site ships on is fully supported and patched.
- **`postcss`** — pinned via an `overrides` entry to a patched `8.5.x`, clearing the PostCSS advisories.
- **`sharp`** — Next's optional image-optimization dependency is pinned via `overrides` to `0.35.3`, which resolves the bundled-libvips advisories. (This site uses no `next/image`, so `sharp` is never invoked at runtime regardless.)
- **`brace-expansion` / ESLint toolchain** — the only remaining high-severity `npm audit` entries are a development-only regex-DoS advisory in the ESLint dependency tree (`brace-expansion` / `minimatch`). These are devDependencies used only when running `npm run lint`; they are **not** part of the production build and never reach the deployed site. Their only upstream fix is a future major ESLint release, so they are tracked rather than force-patched (which would risk breaking linting).

## Resume content and the downloadable PDF

Resume wording (summary, roles, bullets, skills, certifications, education) lives in one place: `lib/content/resume.ts`. Both `/resume` (the HTML page) and the downloadable PDF are generated from that same file, so there is no separate copy of the resume text to keep in sync.

**Regenerating the PDF** after editing `lib/content/resume.ts`:

```bash
pip install weasyprint
npm run resume:pdf
```

This runs `scripts/resume-pdf/generate.sh`, which:
1. Extracts `lib/content/resume.ts` (via esbuild) into plain data.
2. Builds a standalone print HTML document from that data (no site header/footer/nav/download button — print-only).
3. Renders it to `public/resume/camille-lin-resume.pdf` with WeasyPrint, using the dedicated print stylesheet at `scripts/resume-pdf/print.css` (US Letter, ~0.58in margins, local Outfit/Instrument Sans fonts, `break-inside: avoid` on each role so a job entry never splits across pages with an orphaned bullet).

The generated `resume-data.json` and `resume-print.html` intermediate files are deleted automatically at the end of the script — they're build output, not source.

## Deploying to your personal Vercel account

1. Push this repository to **your own personal GitHub account** (not an organization account tied to any employer).
2. Go to https://vercel.com, sign in with your personal account, choose **Add New → Project**, and import the GitHub repo.
3. Framework preset: Vercel auto-detects Next.js — no configuration needed.
4. No environment variables are required to deploy successfully. Add `NEXT_PUBLIC_SITE_URL` afterward per the section above once you know your real URL.
5. Deploy. Vercel gives you a `*.vercel.app` URL immediately; add a personal custom domain later under Project → Settings → Domains if you'd like one.

## Moving to a different host later

This is a standard static-first Next.js app with no Vercel-specific features. It can be redeployed to:
- **Netlify** (via the official Next.js runtime plugin)
- **Cloudflare Pages** (via `@cloudflare/next-on-pages`)
- **Any Node host** — run `npm run build && npm run start` behind a reverse proxy
- **Fully static hosts** (GitHub Pages, S3 + CloudFront, etc.) — would require adding `output: "export"` to `next.config.mjs` and replacing the one edge-runtime route (`app/opengraph-image.tsx`) with a static image, since static export doesn't support on-demand image generation.

## Accessibility

- Single `<h1>` per page, strict heading order (h2 → h3, no skipped levels).
- Skip-to-content link, visible focus states, keyboard-operable mobile navigation with `aria-expanded`.
- All tables are real semantic `<table>` elements with `<th scope="col">`. Comparison tables reflow into labeled cards on narrow screens; the denser data tables scroll horizontally inside a keyboard-focusable, labeled `role="region"` container so scrollable content is always reachable without a mouse.
- Decorative icons are `aria-hidden`; status/before-after distinctions pair color with a text label.
- `prefers-reduced-motion` is respected globally (see `app/globals.css`).
- The downloadable resume PDF (`public/resume/camille-lin-resume.pdf`) is generated by printing the resume's semantic HTML to PDF with WeasyPrint, requesting a tagged, PDF/UA-1 output (`--pdf-tags --pdf-variant pdf/ua-1`). Verified directly on the shipped file with `pypdf`: `/StructTreeRoot` is present in the document's structure tree, so this PDF **is** a real tagged PDF, not just a visual approximation of one. The `/resume` page remains the primary accessible, fully semantic version of the same content, and is what the header/footer "Resume" links point to; the PDF is the downloadable print counterpart.
- All fonts in the PDF (Outfit for headings, Instrument Sans for body text) are embedded and subsetted — verified with `pdffonts public/resume/camille-lin-resume.pdf`, which reports `emb=yes, sub=yes` for every font used, with no fallback to a base-14 PDF font like Helvetica.
- Audited with axe-core (WCAG 2.0/2.1 A + AA) across all six content routes: **0 critical and 0 serious violations**. Re-running Lighthouse or axe against the live production URL after deployment is still recommended as a final check.
